Аутентифицируйтесь от имени сервисного аккаунта с помощью авторизованного ключа

Вы можете создать авторизованный ключ с неограниченным сроком жизни и постоянно аутентифицироваться в Yandex Cloud CLI с его помощью. Использование долгоживущего ключа менее безопасно, чем использование имперсонации.

Для получения авторизованного ключа требуется изначальная аутентификация в CLI аккаунтом Яндекса, федеративным аккаунтом или аккаунтом локального пользователя с помощью устройства с браузером и графическим интерфейсом. Дальнейшая работа с CLI может выполняться на сервере без графического интерфейса.

    Установите CLI.

    Аутентифицируйтесь в CLI как пользователь Яндекса, федеративный пользователь или локальный пользователь.

    Важно

    Аутентификация в CLI аккаунтом Яндекса, федеративным аккаунтом и аккаунтом локального пользователя осуществляется с помощью браузера и графического интерфейса.

    Если вы хотите использовать сервисный аккаунт для работы на сервере без графического интерфейса, выполните подготовительные действия на устройстве с графическим интерфейсом и браузером.

    Создайте авторизованный ключ и аутентифицируйтесь им в CLI:

        Получите список сервисных аккаунтов, которые существуют в вашем облаке:

        yc iam service-account --folder-id <идентификатор_каталога> list

Где --folder-id — идентификатор каталога.

Результат:

+----------------------+------------+--------+---------------------+-----------------------+
|          ID          |    NAME    | LABELS |     CREATED AT      | LAST AUTHENTICATED AT |
+----------------------+------------+--------+---------------------+-----------------------+
| ajeg2b2et02f******** | my-robot   |        | 2024-09-08 18:59:45 | 2025-08-21 06:40:00   |
| ajegtlf2q28a******** | default-sa |        | 2023-06-27 16:18:18 | 2025-08-21 06:30:00   |
+----------------------+------------+--------+---------------------+-----------------------+

Создайте авторизованный ключ для сервисного аккаунта и сохраните его в файл key.json:

yc iam key create \
  --service-account-name default-sa \
  --output key.json \
  --folder-id <идентификатор_каталога>

Где:

    --service-account-name — имя сервисного аккаунта, полученное ранее.
    --output — имя файла, в котором будет сохранен авторизованный ключ.
    --folder-id — идентификатор каталога с сервисным аккаунтом.

Результат:

id: aje83v701b1u********
service_account_id: aje3932acd0c********
created_at: "2019-08-26T12:31:25Z"
key_algorithm: RSA_2048

Если вы создали авторизованный ключ на локальной машине и хотите использовать его для аутентификации в CLI на ВМ, предварительно скопируйте его по SCP.

Добавьте авторизованный ключ сервисного аккаунта в профиль CLI.

    Создайте новый профиль CLI:

    yc config profile create sa-profile

Добавьте авторизованный ключ:

yc config set service-account-key key.json

Убедитесь, что параметры для сервисного аккаунта добавлены верно:

yc config list

Результат:

service-account-key:
  id: aje83v701b1u********
  service_account_id: aje3932acd0c********
  created_at: "2019-08-26T12:31:25Z"
  key_algorithm: RSA_2048
  public_key: |
    -----BEGIN PUBLIC KEY-----
    MIIBIjANBg...
    -----END PUBLIC KEY-----
  private_key: |
    -----BEGIN PRIVATE KEY-----
    MIIEvwIBAD...
    -----END PRIVATE KEY-----

Настройте профиль для запуска команд.

Для некоторых команд требуется указание уникального идентификатора облака и каталога. Вы можете указать информацию о них в профиле или запускать такие команды с соответствующим флагом.

    Укажите облако в профиле:

    yc config set cloud-id <идентификатор_облака>

Или запускайте команды с параметром --cloud-id.

Подробнее на странице Получение идентификатора облака.

Укажите каталог в профиле:

yc config set folder-id <идентификатор_каталога>

    Или запускайте команды с параметром --folder-id.

    Подробнее на странице Получение идентификатора каталога.

Все операции в этом профиле будут выполняться от имени привязанного сервисного аккаунта. Вы можете изменить параметры профиля или сменить его.
